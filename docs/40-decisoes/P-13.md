# P-13 — Isolamento do cutover paralelo não cobre mudanças no MySQL do host

O incidente de provisionamento em homologação (loop de crash do MySQL por `bind-address`
mal configurado — ver [[ADR-08]]) afetou o bare-metal **mesmo com a stack nova ainda não
recebendo tráfego**, porque os dois ambientes compartilham o mesmo banco.

Em produção o mesmo passo rodou sem incidente (o script já incorporava a lição), mas o
risco estrutural — banco compartilhado entre bare-metal e stack nova durante o
provisionamento — permanece. Vale o mesmo cuidado em qualquer mudança futura de host.

Ver [[ADR-04]].
