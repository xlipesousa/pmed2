# P-18 — `registrarPagamento` não verifica a localização do pacote

A [[Sobre a especificação original|especificação original]] exige que a ação "Informar
Pagamento" só esteja disponível quando `localizacao_atual` for **SIRE ou Glosa**.

A implementação (`PacotesController.php:879`) verifica apenas o papel:

```php
if (!Auth::user()->isAdmin() && !Auth::user()->hasRole('sire')) {
    // nega
}
```

Compare com a ação irmã `registrarAguardandoLimite()` (linha 952), que implementa a regra
corretamente:

```php
if (!($user->role === 'admin' || ($user->role === 'sire'
    && in_array($pacote->localizacao_atual, ['sire', 'glosa'])))) {
```

## Efeito

Um usuário do perfil `sire` pode registrar pagamento em pacote que já está em `arquivo` ou
`arquivado` — alterando `valor_pago` e `valor_pendente` de um pacote com ciclo de vida
encerrado. A única barreira remanescente é `valor_pendente > 0`, que num pacote arquivado
normalmente é zero — mas não há garantia disso para pacotes arquivados por outros caminhos.

## Correção

Alinhar a guarda com a de `registrarAguardandoLimite()`. É uma mudança de duas linhas, mas
entra junto com [[P-19|a revisão de autorização]] (item F4.1 do plano de normalização),
porque a correção certa é mover essa checagem para uma Policy em vez de replicar o `if` uma
terceira vez.
