# P-25 — `diffInDays()` do Carbon 3 retorna float, não inteiro truncado

Descoberto ao verificar `specs/003-relatorio-prazo-glosa/` em execução real: o novo método
`Pacote::diasDesdeRetiradaOficio()` exibia **"45.00152993125 dias"** em vez de "45 dias".

## Causa

Carbon 3 (usado por este projeto em Laravel 12) mudou o comportamento de `diffInDays()` e
métodos semelhantes: eles passaram a retornar o valor **preciso** (float), em vez de truncar
para inteiro como no Carbon 2. Qualquer código escrito assumindo o comportamento antigo
exibe frações de dia.

## Onde já foi corrigido

`Pacote::diasDesdeRetiradaOficio()` — `(int)` explícito, com comentário explicando o porquê.

## Onde provavelmente ainda existe

`Pacote::diasRetiradaRestantes()` (`app/Models/Pacote.php`, método pré-existente, não
modificado nesta spec) usa o mesmo padrão:

```php
return now()->diffInDays($this->data_limite_retirada, false);
```

Não verificado em produção, mas é o mesmo Carbon, o mesmo padrão de chamada — a suspeita é
forte. Esse método alimenta a tela `pacotes.prazos` e o card de alerta do dashboard
(`DashboardHelper::getPacotesComAlerta` / `dashboard.blade.php`), então uma fração de dia
apareceria diretamente para o usuário final.

## Correção

Não corrigida agora — é código pré-existente fora do escopo desta spec, e mudar
comportamento de exibição sem teste de caracterização vai contra a regra de F3 do plano de
normalização. Confirmar o sintoma em produção/homolog e corrigir com `(int)` ou
`->floor()`, junto de um teste que trave o formato de saída.
